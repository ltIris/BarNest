# BarNest

BarNest 是一款用 Swift 和 AppKit 编写的 macOS 菜单栏收纳工具。它把选中的第三方菜单栏图标收进系统溢出区，并在一个面板中集中展示和操作。

## 为什么做这个项目

从 macOS 26 开始，菜单栏的实现和外部可用接口发生了变化，iBar Pro 等工具原有的部分功能受到影响。我一直在等熟悉的工具适配，但等了半年仍没有等到满足自己需求的版本，于是开始做 BarNest。

我希望它免费、开放源码，不设置付费门槛。这个项目仍在迭代，也欢迎大家查看代码、反馈问题和参与改进。

## 当前功能

- 扫描当前菜单栏中的第三方图标，在工作台中集中展示。
- 在偏好设置中选择要收纳的图标，并调整展示顺序。
- 点击工作台图标，尝试打开原应用的菜单栏菜单；无法打开时激活应用。
- 通过右键菜单激活、隐藏或退出应用，并提供常用窗口位置操作。
- 展示正在播放的应用，以及 CPU、内存、磁盘和网络用量。
- 根据当前屏幕显示工作台；点击面板外部可关闭。
- 提供恢复入口，避免收纳后找不到菜单栏按钮。

## 使用方式

1. 启动 BarNest，按需在「系统设置 → 隐私与安全性 → 辅助功能」中授权。扫描真实菜单栏图标、触发原菜单和窗口操作需要此权限。
2. 右键点击 BarNest 菜单栏图标，打开「偏好设置」选择要收纳的应用。
3. 使用菜单栏图标或 `⌥⌘N` 打开工作台。若图标不可见，可以通过热键打开。
4. 需要恢复菜单栏图标时，使用右键菜单中的恢复操作，或按 `⌥⌘R`。退出应用时也会释放收纳状态。

未获得辅助功能权限时，BarNest 无法扫描菜单栏图标，图标列表可能为空；原菜单和窗口操作也可能不可用。

## 从源码构建

在项目目录运行：

```bash
./build.sh
```

脚本使用 `swiftc` 构建 Apple Silicon 版本，目标为 `arm64-apple-macosx27.2`，产物位于 `.build/BarNest.app`。需要安装支持此目标版本的 Xcode 和 macOS SDK。脚本会优先使用本机名为 `NotchTool Local Signing` 的签名身份；没有该身份时尝试临时签名。自行分发应用还需要处理签名和公证。

## 实现与兼容性

BarNest 使用辅助功能接口读取菜单栏图标，并通过系统私有的 `MenuBarClientCore.framework` 管理收纳状态。私有接口可能随 macOS 更新而变化，相关功能无法保证在每个系统版本上都正常工作。当前构建脚本针对 macOS 27.2；macOS 26 上的实际兼容性仍需验证。

### 系统菜单栏的兼容限制

- **正在播放图标：**当前系统的收纳断言会连带影响官方「正在播放」菜单栏模块。即使把相关系统项加入允许列表，也无法稳定地让该图标始终留在菜单栏。BarNest 因此在工作台提供播放入口，并在需要时临时释放收纳断言。这是对系统现有行为的部分兼容，播放图标可能短暂消失或随收纳状态变化。
- **时间日期等系统组件：**收纳断言生效时，点击时间日期、控制中心等系统项可能无法弹出官方组件。BarNest 会在点击时临时恢复系统菜单栏的原始展示，此时已收纳的图标可能全部展开；待组件关闭后再尝试重新收纳。当前没有可靠方式在保持图标收纳的同时直接调用这些官方组件，因此无法做到完全无感切换。

温度和 GPU 指标目前没有真实采集，界面中若出现对应数值，不应将其用于系统监控。
